## Earlier conformance summary

The bundled corpus contains **6,274 selected expression cases** from a pinned Microsoft Power Fx revision, with source links, upstream expected expressions, independently encoded expected JSON, and the Microsoft MIT notice. The harness runs entirely in Python without internet or .NET. It reports **6,264 passes, ten known gaps, and zero unexpected regressions** on the current implementation. This selection covers single-column text/substring/replacement/concatenation, Abs/rounding and math overloads, text conversion, record/table shaping, sorting and custom order tables, count/index overloads, table unions/coercions, embedded errors, typed Blank, With/ThisRecord/aliases, ForAll, lazy IfError handling, date boundaries, localized parsing, Text formatting, and Decimal/Float conversion, rounding and remainder, plus all 20 pure-record Patch cases, all 33 cases in the pinned Remove reference file and all 30 StdevP/VarP expressions in both numeric modes, and 450 scalar/table Sum/Average/Min/Max cases. Four additional cases expose the same documented Canvas relative-year versus pinned engine absolute-year difference already reported by the date corpus. Removal cases run in disposable runtimes with the upstream fixture records and display-name aliases; they never change the caller’s app or database. It is not the complete Microsoft suite or proof of general Power Apps compatibility.

The ten selected-case gaps are six involving the canvas/engine year rule, three requiring Spanish or Japanese locale support, and Dec2Hex negative-fraction truncation versus the pinned engine’s flooring. Known mismatches stay visible in the report rather than being skipped or marked as passes. Use --strict to return an unsuccessful exit status for any gap; the default fails for unexpected regressions. Reference cases live in powerapps_sim/conformance_cases/, including core.json, table_overloads.json, counts.json, row-counts.json, queries.json and search.json. Temporal, numeric, and scalar-table cases explicitly select reference host profiles where needed; ordinary projects keep the canvas defaults. Embedded error expectations compare numeric ErrorKind; diagnostic wording can vary between hosts.

## Implementation status against the original plan

Assessment: **11 October 2026**. “Implemented” means covered for the documented sample patterns, not general equivalence to Power Apps. Counts and passing tests describe local evidence, not Microsoft certification.

User-defined types support forward references, nested record/table shapes, scalar tables with a Value column, and `RecordOf` applied to a declared table type. Function records may contain a subset of declared fields; missing fields become Blank, while extra fields are rejected, including in typed empty tables. Use ShowColumns to project list records (which also contain metadata) into the desired contract. These rules follow [Microsoft’s Type and RecordOf reference](https://learn.microsoft.com/en-us/power-platform/power-fx/reference/function-type) and [user-defined function contracts](https://learn.microsoft.com/en-us/power-platform/power-fx/reference/object-app#user-defined-functions).

```powerfx
ProjectRow := Type(RecordOf(ProjectTable));
ProjectTable := Type([{Title: Text, Amount: Number}]);
AmountOf(row: ProjectRow): Number = Coalesce(row.Amount, 0);
```

Type aliases are declarations, not runtime values. Invalid declarations report source diagnostics; invalid signatures are blocked before actions execute. Field errors remain separate from Blank and can stay lazy when another field is read. Typed Blank tables use table aggregate semantics. Additional coercion families and Studio paste acceptance still need comparison.

Create the fictional type fixture with `python -m powerapps_sim.fixtures projects/types-check --kind types`, then open it with `python -m powerapps_sim --import projects/types-check`. Its 21-step workflow exercises list projection, typed sorting and aggregation, partial records, two isolated component instances, event callbacks and a SQLite write. Source, list configuration and workflow are separate. Modern Text and classic Label controls with authored OnSelect events support pointer selection and Enter/Space activation in the preview, following [Microsoft’s modern Text behavior](https://learn.microsoft.com/en-us/power-apps/maker/canvas-apps/controls/modern-controls/modern-control-text).

Typed app functions now apply V1-compatible scalar coercions to parameters and return values: numeric/Text/Boolean conversions, Text/temporal conversions, temporal kind conversion, GUID/Text identity, and Dynamic scalar constructors. Compatible fields also convert recursively inside restrictive records and tables; a record can supply a one-row table. Missing fields become Blank and extra fields remain errors. Invalid scalar text is bindable but fails at runtime. Failed aggregate cells stay lazy, so a function reading a healthy field can still succeed. Statically incompatible argument schemas are rejected before evaluating the call arguments. Numeric/date conversions follow the selected host profile; Float and Decimal text use the simulated language. These rules are compared with Microsoft's [UDF type checks](https://github.com/microsoft/Power-Fx/blob/main/src/libraries/Microsoft.PowerFx.Core/Functions/UserDefinedFunction.cs), [coercion rules](https://github.com/microsoft/Power-Fx/blob/main/src/libraries/Microsoft.PowerFx.Core/Types/DType.cs) and [interpreter conversions](https://github.com/microsoft/Power-Fx/blob/main/src/libraries/Microsoft.PowerFx.Interpreter/Functions/LibraryUnary.cs). Typed JSON conversion remains stricter about JSON scalar kinds. Enhanced component contracts are covered below; Dataverse/option-set types and exact Studio behavior still need comparison.

```powerfx
Amount(value: Text): Number = value;
Entry := Type({Title: Text, Amount: Number, Enabled: Boolean});
Normalize(row: Entry): Entry = row;
// Returns {Title: "100", Amount: 12.5, Enabled: true}
Normalize({Title: 100, Amount: "12.5", Enabled: "true"})
```

Typed ParseJSON, AsType and IsType accept declared aliases, primitive names and inline Type specifications. They project declared fields, fill missing fields with Blank and ignore extra fields. Scalar kinds remain strict: a JSON string containing digits does not satisfy Number, although explicit Value can convert it. Nested failures report the JSON path. IsType returns false for a conversion mismatch and propagates errors evaluating its input. Ordinary Text URLs remain text; imported media resources retain media identity. Logical list names survive table shaping, typed value coercion and variable storage through internal record metadata, excluded from exported source. [Microsoft’s JSON reference](https://learn.microsoft.com/en-us/power-platform/power-fx/reference/function-json) describes these contracts. ## Structure and AI workflow

The Python runtime stays authoritative and project files are the authored source of truth. `application.py`, `authoring.py`, `catalog.py` and `ownership.py` provide the shared foundation; `ai_service.py` exposes project operations and `mcp_server.py` adds the optional protocol adapter. The broader package/directory reorganization below remains a proposal:

```text
powerapps_sim/
  engine/                 # parsing, binding, evaluation, controls, layout
  application/            # project/source/schema/changes/scenario services
  storage/                # SQLite simulation adapter
  adapters/http/          # current Flask/browser interface
  adapters/mcp/           # optional AI tools and resources
  adapters/sharepoint/    # optional future online connector

app-project/
  Src/                    # Power Apps source only
  Assets/
  lists/                  # canonical list definitions, mappings, options, relationships
  fixtures/               # explicitly fictional datasets and roles
  tests/                  # declarative application scenarios and expected outcomes
  migrations/             # reviewed schema/data changes
  metadata/               # imported archive/checker evidence
  .emu/                   # database, drafts, environment configuration and caches
```

Current engine modules remain flat. `application.Workspace` owns the runtime and lock; Flask imports it and routes authoring changes through `AuthoringService`. Current projects use `Src/`, `Assets/`, `lists/`, `metadata/`, `drafts/`, `emulator.json`, `data.sqlite`, `tests/*.workflow.json`, `.emu/changes/` and `.emu/runs/`. Move modules only when it helps. Imported private projects stay outside tracked simulator code. Choice/lookup gaps must remain distinguishable from authored fixture configuration.

`lists/*.json` now stores the canonical authored schemas. SQLite holds materialized definitions and simulation records. Source/schema revisions, staged combined diffs, record-impact checks and migration backups are implemented. Browser writes and headless CLI changes use the same service. External schema edits load on explicit restart after validation; a running workspace rejects authoring changes while the catalog differs from its materialized schemas.

The browser and MCP adapter use **one workspace owner** for a given open project. A standard-library OS project lock now rejects a second Workspace/CLI owner; restart and project switching retain/release ownership correctly. A local stdio MCP process can forward to the running simulator's service API; headless use can host the same services without a browser. Do not launch a second independent Runtime against the browser's database: globals, caches, selected screens and pending edits would diverge. Keep MCP an optional dependency so offline simulation retains its small installation.

MCP exposes structured tools/resources to different AI clients. It supplies access to the project; the AI host supplies the model. The adapter uses local stdio and the pinned [official Python SDK](https://py.sdk.modelcontextprotocol.io/). Remote/multiuser hosting and embedded AI chat remain future requirements.

Implemented operations:

- Read project/screen/control/component source, schemas, current diagnostics, inferred types and dependency information.

- Run a named scenario in an isolated dataset/session, returning events, assertions and diagnostics without changing the open preview.
- Apply a validated local change with rollback metadata, or export Power Apps code and list definitions for review.

Use typed project operations rather than arbitrary Python/SQL execution. Preserve errors and app access rules; a successful simulated test must not depend on bypassing them. No automatic live write is implied by a local Patch or schema edit.
